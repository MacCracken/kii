Frame is 7,441 bytes of ANSI escape sequences (32 rows; 14,553 at v1.9.0–2.0.1,
~54 KB before v1.8.0's elision). First bytes:

  \x1b[90m\x1b[40m▄█\x1b[47m▀▀    \x1b[97m▄▀██▀▀█▀█  ▀▀▀▀███▀█ ...

(v2.1.0 chose each cell's glyph for fewest escapes, so these bytes changed
again while every cell kept its two colours: 14,553 → 7,441. They read
`\x1b[30m\x1b[100m▀\x1b[90m▀\x1b[47m▀▀\x1b[37m▀▀▀▀…` at v1.9.0–2.0.1, and
`\x1b[30m\x1b[40m▀\x1b[100m▀…` at v1.8.0.)

Format: per cell, `SGR foreground; SGR background; ▀` (U+2580 half-block),
where the foreground carries the top pixel's colour and the background the
bottom pixel's. Since v2.1.0 the same two colours may come as `▄` with the
roles swapped, and a one-colour cell as a space (background) or `█`
(foreground), whichever needs fewer escapes; at 16 colours a bright colour
stays in the foreground (ADR 0004 § v2.1.0). Since v1.8.0 (ADR 0010) an escape is written only when it
changes from the previous cell in the same row, and the default 16-colour
tier uses the plain SGR codes (30–37 / 90–97 foreground, 40–47 / 100–107
background) rather than `38;5;N` / `48;5;N`. Every row ends with an explicit
SGR reset (`ESC [ 0 m`) before its newline, so the frame cannot leave the
terminal in a coloured state and the next shell prompt isn't tinted.
`kii --width 80 … | tail -c 5` is `ESC [ 0 m \n`.

Run produces exit code 0, no stderr output (unless --verbose).
